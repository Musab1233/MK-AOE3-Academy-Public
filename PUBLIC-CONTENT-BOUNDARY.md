# Public Content Boundary

## Purpose

This document defines the standing boundary between the public Academy presentation repository and the private Academy working estate.

Public repository visibility is not authorization to disclose additional material. Each new content batch must remain within this boundary and receive the required owner approval before publication.

## Approved content classes

This repository is limited to:

- Public Academy mission and scope summaries.
- Public explanations of AOE3 concepts and evidence distinctions.
- High-level standards-family scope summaries with accurate development status.
- High-level Body of Knowledge and proposed certification-pathway descriptions.
- Broad research themes and public controlled-disclosure policy summaries that identify no live candidate or private working content.
- Synthetic educational examples that contain no real transaction, person, organization, credential, or confidential event.
- Public legal, copyright, privacy, and non-claim notices.
- The static website source required to present that material.

## Prohibited content classes

Do not place the following in this repository, its history, issues, pull requests, releases, actions, pages, or attachments:

- Full normative standards, controlled candidate drafts, or private source archives.
- Governance, decision, risk, curriculum, examination, improvement, research, disclosure, or evidence registers.
- Live research-candidate titles, abstracts, drafts, reviewer comments, private research evidence, working notes, disclosure history, or confidential collaboration material.
- Examination banks, model answers, assessment logic, learner records, or credential-holder personal data.
- Track A material, canonical evidence, owner-restricted release records, internal custodian material, or incident records.
- Private keys, signing material, passwords, API keys, tokens, OTPs, recovery codes, account-recovery details, or confidential contact data.
- Unreleased partnership material or any implication of a signed partnership, endorsement, or accreditation.
- Material whose public classification or owner approval is uncertain.

## Claims discipline

The website must not imply that:

- A Draft or Planned standard is ratified.
- A proposed certification is awarded, accredited, or independently recognized.
- A simulation or synthetic teaching case proves production performance or security efficacy.
- Repository access confers ownership, licensing, release authority, or publication rights.
- A signature or hash proves occurrence, execution truth, ownership, authorization, or qualification.

## Change control

1. Review both language versions and all linked assets.
2. Confirm that status labels match the controlling owner-approved position.
3. Scan the complete change set for prohibited content and secrets.
4. Verify navigation, language switching, responsive layouts, reduced motion, and local inquiry behavior.
5. Recompute the external SHA-256 manifest after the final edits.
6. Keep private working records in the private Academy repository.
7. Treat repository creation, upload, deployment, and later publication as separate controlled actions.
8. For research, approve only the exact public summary, audience, version, and channel; never inherit approval for the underlying research or later versions.

When classification is uncertain, the material stays out. For research disclosure, the state remains HOLD.
